## 実装メモ

`docs/attribute-contract.md` は、supported attributes の一覧だけではなく、どの属性が request-capable な状態を作るのかを明記した。ここで request-capable とは、実際に network request を実行できる設定を持つ状態という意味で、`mx-trigger` だけを持つ要素は request を発火しない。

request attribute は precedence を持たないことにした。つまり `mx-get` と `mx-post` が同じ要素にある場合にどちらかを選ぶのではなく、`MHX_VALIDATE_CONFLICTING_REQUEST_METHODS` で拒否する。これは現在の `first_validation_error` の実装と合わせている。

`mx-target` は trigger-local `target:`、element-level `mx-target`、triggering element の順で解決される。bare な `closest` / `find` / `next` / `previous` は selector として未完成なので、`MHX_PARSE_INVALID_SELECTOR` として扱うことを明文化した。

`mx-vals` は flat JSON scalar だけを許可する。flat JSON scalar とは、値が string / number / boolean / null のどれかで、object や array を含まない JSON object のこと。form body との merge では form fields の後ろに `mx-vals` を追加するため、同じ key を map として解釈する利用者には後勝ちとして見える。

## 計画: trigger DSL spec

`issues/2026-05-05T151155-spec-stabilize-trigger-dsl.md` に対応する。
`mx-trigger` は request をいつ schedule するかを決める小さな DSL なので、DOM や network の runtime から切り離して parser contract として読める状態にする。

具体的には次を行う。

- `docs/trigger-spec.md` に event name、`load` / `revealed` / `intersect`、filter、modifier、duration、selector、queue、parse error behavior を書く。
- parser の公開 API だけを使う golden test を追加し、DOM / network に依存しないことを保つ。
- issue にある supported examples と、既存実装が持つ selector / queue / multiple trigger の形を fixture にする。
- invalid expression は input と parse error を一緒に記録し、position と reason が読めるようにする。
- README から trigger spec への導線を明確にし、issue を closed に移動する。

## 実装メモ: trigger DSL spec

parser は `f4ah6o/mhx-spec/parser` にあり、この repository では runtime 側から使っている。今回は parser 自体の API を広げず、repo-local の blackbox test として `src/event/trigger_golden_test.mbt` を追加した。blackbox test とは package の公開 API だけを見るテストという意味で、内部 scanner の private function には触れない。

golden は `json_inspect` で AST の JSON 表現を固定した。modifier の順序も source order のまま出るため、`click[ctrlKey] changed once ...` のように複数 modifier を並べた fixture で deterministic な出力を確認できる。

duration は現在の parser が integer だけを読む。`1s` は `1000ms` に変換されるが、`1.5s` は仕様として受けないことを docs に明記した。fractional second が必要な場合は `1500ms` と書く方針にした。

parse error fixture は `("input", Err(...))` の形で inspect している。これにより、元の入力、`offset` と `char` を持つ position、`expected` または invalid value が 1 つの golden として確認できる。
