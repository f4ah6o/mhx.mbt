# Versioning policy

This repository intentionally tracks two version domains.

## MoonBit package version

The MoonBit package surface is versioned by:

- `moon.mod.json`
- `src/lib.mbt` (`@mhx.version`)

These values must stay identical.
README examples that install `f4ah6o/mhx` must use this version domain.

## npm/runtime version

The browser package surface is versioned by:

- `package.json.version`
- the bundled JavaScript `version` export generated by `npm/postbuild.mjs`
- release tags used for npm publication, formatted as `v<package.json.version>`

README npm examples, CDN URLs, and Subresource Integrity commands must use this
version domain.

## Why two domains exist

The MoonBit module and npm/browser runtime move at different cadences.
The MoonBit package follows the library/module contract, while the browser package follows the published JS runtime contract.

## Guardrails

- `pnpm verify:versions` checks MoonBit version consistency, README MoonBit
  install examples, README npm CDN examples, and this policy document
- `pnpm build` verifies the npm package surface after bundling and confirms the
  generated JavaScript `version` export matches `package.json.version`
- README examples should avoid mixing MoonBit package versions with npm package versions

## Release checklist

Before creating a release tag:

1. Update `moon.mod.json` and `src/lib.mbt` together when the MoonBit package
   contract changes.
2. Update `package.json.version` when the npm/browser runtime contract changes.
3. Keep README MoonBit install examples aligned with `moon.mod.json`.
4. Keep README npm CDN examples aligned with `package.json.version`.
5. Run `pnpm verify:versions` to catch version drift before building.
6. Run `pnpm build` so the bundled JavaScript `version` export and package
   smoke tests are checked.
7. Create npm release tags as `v<package.json.version>`.
